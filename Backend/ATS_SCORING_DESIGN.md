# ATS Scoring Design (Phase 6.1)

## Goal

Create a deterministic ATS-style score out of 100 that is explainable, reproducible, and based on extracted resume text only. This score is not generated by Gemini and does not depend on subjective LLM judgment. It is designed to support a future job-description matching layer without changing the current scoring structure.

The score is intended to evaluate resumes fairly for students, graduates, and early-career applicants. It should reward clear evidence of relevant experience, skills, and structure without harshly penalizing missing corporate experience when the resume is otherwise complete.

---

## Scoring model

Total score: 100 points

| Category | Max Points | Purpose |
|---|---:|---|
| Keyword Optimization | 30 | Measures how well the resume demonstrates relevant technical and professional language using general ATS-style keyword signals |
| Resume Structure | 20 | Checks whether the resume has identifiable sections and a coherent content layout |
| Content Completeness | 20 | Evaluates whether the resume includes critical information expected from a strong candidate profile |
| Skills Relevance | 20 | Checks whether the resume highlights relevant skills and technology areas appropriately |
| Formatting / Readability | 10 | Evaluates readability using extracted text only, not visual PDF layout |

Total: 100

---

## 1) Keyword Optimization — 30 points

### Purpose

This category rewards resumes that include a strong set of relevant general keywords without overstuffing. Since no Job Description is available yet, the evaluation uses a curated general keyword list for common technology and professional domains.

### Evaluation inputs

Use the extracted resume text and a predefined keyword dictionary grouped by domain, for example:

- Programming: Python, JavaScript, Java, C++, SQL, R, TypeScript
- Web / backend: FastAPI, Flask, Node.js, REST, APIs
- Data / AI: Machine Learning, AI, Deep Learning, NLP, Computer Vision, Data Analysis, Pandas, NumPy
- Cloud / tooling: Git, Docker, AWS, GCP, Azure, Linux, CI/CD
- Business skills: Communication, Leadership, Research, Problem Solving, Project Management

### Deterministic scoring

Score = min(30, sum of category sub-scores):

1. Technical keyword coverage (12 points)
   - 12 points: 6+ high-value technical keywords found
   - 8 points: 4-5 keywords found
   - 4 points: 2-3 keywords found
   - 0 points: 0-1 keywords found

2. Role / domain keyword coverage (10 points)
   - 10 points: keywords spanning multiple meaningful domains (e.g., programming + AI + tools)
   - 6 points: keywords from at least two domains
   - 3 points: keywords from one domain
   - 0 points: nearly none

3. Keyword quality / no stuffing (8 points)
   - 8 points: keywords appear naturally across skills, projects, and summary sections
   - 4 points: keywords are present but concentrated in one place or repeated excessively
   - 0 points: keyword stuffing or mostly irrelevant terms

### Notes

- This is intentionally general-purpose and not tied to a single job description.
- It should reward relevant skills without penalizing entry-level candidates for having a shorter or less extensive resume.
- In the future, this section can become job-specific via an optional JD keyword set without changing the category structure.

---

## 2) Resume Structure — 20 points

### Purpose

Resumes should have a clear structure that ATS systems can interpret and recruiters can scan quickly.

### Evaluation inputs

The extracted text is checked for section headers and meaningful content blocks.

### Deterministic scoring

1. Required section headers (10 points)
   - 2 points each for: Contact, Summary/Objective, Experience, Education, Skills, Projects/Work Samples
   - Cap at 10

2. Content organization (6 points)
   - 6 points: sections are clearly separated and ordered logically
   - 3 points: sections are present but not clearly organized
   - 0 points: no sensible layout or all content merged together

3. Chronology / progression (4 points)
   - 4 points: includes dates, durations, or a clear order of experience/education
   - 2 points: partial chronology only
   - 0 points: no chronology or no usable ordering cues

### Notes

- For students, project and coursework sections can substitute for some missing corporate experience.
- This is based on extracted text structure only, not on visual PDF formatting.

---

## 3) Content Completeness — 20 points

### Purpose

A resume should include enough information to give recruiters confidence in the candidate's capabilities.

### Deterministic scoring

1. Core identity and contact information (4 points)
   - 4 points: name + email or phone or location present
   - 2 points: partial contact details only
   - 0 points: missing or unusable

2. Experience / projects / internships evidence (6 points)
   - 6 points: clear experience or project section with descriptions and dates
   - 3 points: some experience or project content present but weakly described
   - 0 points: no practical experience evidence

3. Education / academic profile (4 points)
   - 4 points: education section present and clear
   - 2 points: vague or partially present
   - 0 points: absent

4. Skills and technical evidence (3 points)
   - 3 points: meaningful skill list or technical competency evidence present
   - 1-2 points: sparse or weak evidence
   - 0 points: no skills information

5. Impact / outcomes signal (3 points)
   - 3 points: resume contains measurable or concrete outcome language (e.g., built, improved, reduced, shipped, developed)
   - 1-2 points: some evidence but weak
   - 0 points: largely generic or empty descriptions

### Notes

- For entry-level candidates, projects, coursework, capstone work, hackathons, internships, and certifications count as valid evidence.
- This avoids unfairly penalizing candidates with less formal work history.

---

## 4) Skills Relevance — 20 points

### Purpose

This category measures whether the resume highlights skills that are relevant to modern technical and professional work, even without a job description.

### Deterministic scoring

1. Technical stack quality (10 points)
   - 10 points: strong, coherent mix of relevant technologies and tools
   - 6 points: some relevant tools but limited breadth or clarity
   - 3 points: weak or generic technical profile
   - 0 points: no meaningful technical skills

2. Cross-functional relevance (6 points)
   - 6 points: includes at least two useful categories such as technical + teamwork + communication + project execution
   - 3 points: only one category is clearly represented
   - 0 points: mostly unsupported or generic language

3. Skill specificity (4 points)
   - 4 points: skills are specific and concrete rather than vague labels
   - 2 points: moderate specificity
   - 0 points: generic or empty

### Notes

- A resume with strong Python + FastAPI + AI/ML + Git + SQL typically scores highly.
- It should not reward buzzwords alone. Skills must be grounded in evidence from the resume text.

---

## 5) Formatting / Readability — 10 points

### Purpose

This category evaluates how readable the resume is from extracted text, without claiming to analyze visual PDF formatting perfectly.

### What is evaluated

Only text-derived signals are considered:

- Use of clear section headings
- Presence of bullet lists or short line-based entries
- Short, scannable line lengths
- Limited dense paragraphs with no structure
- Clear separation between sections
- Presence of dates or role labels

### Deterministic scoring

1. Text structure readability (6 points)
   - 6 points: clear sections, bullets, concise lines, logical grouping
   - 3 points: partially readable but still dense
   - 0 points: hard to parse or largely one block of text

2. Consistency and scannability (4 points)
   - 4 points: consistent labels and clear formatting cues (dates, bullet patterns, section names)
   - 2 points: some consistency but weak structure
   - 0 points: inconsistent or unreadable

### Important limitation

This is intentionally limited to extracted text readability. It does not attempt to judge visual appearance, spacing, margins, or exact PDF layout.

---

## Point calculation formula

Each category is scored independently using measurable checks.

- Each category has a maximum score.
- Category scores are computed using thresholds and bounded sub-scores.
- Final ATS score is:

`ATS_Score = Keyword_Optimization + Resume_Structure + Content_Completeness + Skills_Relevance + Formatting_Readability`

where each component is in the range `[0, max_points]`.

The final score must be clamped between 0 and 100.

---

## Example scoring logic

Example candidate profile:

- Has a clear summary, skills, projects, and education
- Lists Python, FastAPI, SQL, Git, and AI/ML work
- Has a few project bullet points with weak impact descriptions
- Missing exact contact details and dates in one section
- Resume is easy to scan but light on experience details

Sample score:

| Category | Score |
|---|---:|
| Keyword Optimization | 24/30 |
| Resume Structure | 17/20 |
| Content Completeness | 14/20 |
| Skills Relevance | 18/20 |
| Formatting / Readability | 9/10 |
| Total | 82/100 |

This is explainable because the user can see why the score was not higher: for example, the resume had good skills and structure, but lacked some completeness and stronger outcome language.

---

## Explainability to the user

The final ATS result should not be a single opaque number. It should be returned as:

- `score` (0-100)
- `category_scores` with each category value and max
- `breakdown` with short reasons such as:
  - "Strong technical keyword coverage"
  - "Missing explicit education section"
  - "Resume is well structured but lacks measurable outcomes"
  - "Strong skill relevance in Python and backend tooling"

This keeps the score understandable and actionable.

---

## Integration with the existing resume-analysis pipeline

The current pipeline is:

1. PDF uploaded via FastAPI
2. PDF text extracted in the PDF service
3. Extracted resume text passed to the resume-analysis LLM chain
4. Structured `ResumeAnalysis` returned from Gemini

The ATS score should be computed in a separate deterministic service, following the extracted text stage.

### Proposed integration point

After `extract_text_from_pdf(file)` and before/alongside the Gemini `analyze_resume_text()` call:

- Input: `resume_text`
- Process: deterministic ATS scoring logic over the extracted text
- Output: `ATSScoreResult` object containing:
  - `score`
  - `category_scores`
  - `breakdown`
  - `metadata` such as section presence and keyword hits

### Why this fits the architecture

- It does not depend on the LLM for score generation.
- It uses the same extracted text that is already available in the pipeline.
- It keeps the AI analysis and ATS logic separate and explainable.
- It is easy to extend later with a job description input without redesigning the whole model.

### Future extension

When a job description is added later, the system can optionally add a `job_description_keywords` input and adjust the category weights or add a separate `JD Match` component while preserving the base score model.

---

## Design principles

- Deterministic: no random or opaque model-generated score
- Reproducible: same input text gives the same score
- Fair: student and early-career resumes are not penalized for missing corporate experience if evidence is present elsewhere
- Explainable: score is broken into categories and reasons
- Extensible: job-description matching can be added in a future version without changing the base model
- Text-based only: no claims about visual formatting beyond what can be inferred from extracted text

---

## Proposed Phase 6.1 outcome

This design defines a deterministic ATS score out of 100 using five categories and measurable rules. It is ready for review and can be implemented in Phase 6.2 without changing the current production pipeline or the structured resume analysis model.
